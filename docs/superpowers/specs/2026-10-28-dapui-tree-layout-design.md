# dapui 变量树排版优化 —— 方案（待审核）

> 目标：右侧那栏"函数名、变量、值、类型"混在一起不好读。
>
> **已实现（2026-10-28）**：采用 **A + B 的"类型独立列 / 长值提示"**（表头没做）。
> 你定的那条：**分组标签默认英文**，加配置 `labels = "zh-CN"` 切中文。其余按下面 §5 的建议执行。

---

## 1. 现状（实测截取，release 版）

```
┌─────────────────────────────────┐
│ #1  t743455  │ a=2 b=3 s=5     │   ← 会话行 + 局部摘要挤一行
│▾ ⌚ Watches (1)                 │
│    ⌚ s = 5 :int                │
│▾ add  hello.c:4                 │   ← 当前帧：名字和位置只隔两个空格
│  ▾ Locals                       │
│      a = 2 :int                 │
│      b = 3 :int                 │
│      s = 5 :int                 │
│  ▸ Globals                      │
│  ▸ Registers                    │
│▸ main  hello.c:7                │
│▸ … 3 个系统帧（无源码）         │
└─────────────────────────────────┘
```

### 具体问题（每条都对应代码位置）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 名字/值/类型**没有列**，长短一变就"乱" | 每行是一条拼接字符串：`pad + mark + label + " = " + value`（`render_tree`） |
| 2 | `a = 2 :int` 里 `:int` 挤在值后面 | `format_value()` 把 `:类型`、`(N)`、`[N]` 全拼进 `value` |
| 3 | 长值/长类型互相挤，截断无提示 | `helix.text.truncate(line, w)` 一刀切，不告诉"还有多少" |
| 4 | 层级靠 2 空格缩进，深层吃掉半栏 | `pad = "  ".repeat(depth)`，帧→作用域→变量→成员 = 4 级 = 8 列 |
| 5 | 顶部摘要在有 Locals 时**重复** | `locals_summary(6)` 与下面 `Locals` 展开内容一样 |
| 6 | 分组标签英文（`Watches/Locals/Globals/Registers`），其余提示中文 | 标签硬编码 |
| 7 | `Globals`/`Registers` 常驻占位，多数时候是空的 | 无条件加节点 |
| 8 | `… 3 个系统帧（无源码）` 与正常节点同色，抢注意力 | 同一 `style: null` |

## 2. 方案 A：列对齐 + 分层样式 + 中文分组（**推荐，改动最小**）

思路：**一行 = 三段富文本**（`helix.draw.text` 已支持 `StyledText[]`），而不是一条字符串。

```
▾ 监视 (1)
  │ s            = 5                 int
▾ add()  hello.c:4          ← 帧：函数名加 () + 位置右对齐、暗色
  ▾ 局部 (3)
    │ a          = 2                 int
    │ b          = 3                 int
    │ s          = 5                 int
  ▸ 全局
▸ main()  hello.c:7
  … 还有 3 个系统帧（无源码）        ← 暗色、无括号噪音
```

规则：

| 段 | 宽度 | 样式 |
|---|---|---|
| 缩进 + 折叠符 | 每级 **2** 列，最多显示 **3** 级（更深用 `┆` 提示） | `ui.virtual` |
| 名字 | `min(40%, 最长名字+2)` | 变量 `ui.text`；帧 `ui.text.focus`；作用域 `ui.text.focus` |
| 值 | 占剩余，`= ` 起头 | `ui.text` |
| 类型 | 右对齐，放不下**整体省略**（不折断） | `ui.virtual` |
| 错误值 | 整行 | `error` |

配套：
- 分组标签中文化：`监视` / `局部` / `全局` / `寄存器`（保留英文小字？见 §5 待定）
- 顶部摘要**去掉**（Locals 已经有了）；会话行只留 `#1 ⏸ t743455`
- `全局`/`寄存器` 空则**不显示**
- 系统帧折叠行用 `ui.virtual`

**工作量**：约 0.5 天（只动 `render_tree` + `format_value` + 标签，加 4–5 条单测）
**风险**：低。不改数据、不改交互，纯显示层。

## 3. 方案 B：在 A 之上加"表头 + 自适应列 + 长值提示"（中等）

```
▾ 局部 (3)
   名字          值                类型
  │ a         = 2                 int
  │ buf       = "hello wor…"(+42) char[64]
```

- 每个作用域下插一行**暗色表头**（只在展开时出现，占 1 行）
- 列宽：名字列按**当前可见节点**的最长名字自适应（上限 45%）；值列按剩余
- 值超宽：`"hello wor…(+42)` —— 截断处告诉你还有多少字符
- 类型列独立（不再混在值里）
- 树宽默认从 `34` 提到 **40**（可配），中文标签 + 三列才不挤

**工作量**：+0.5 天（列宽计算 + 截断提示 + 表头 + 单测）
**风险**：低；但表头会多占行，小屏/窄栏下可能想关 → 给配置 `show_columns_header`（默认关，见 §5）。

## 4. 方案 C：分区（监视 / 栈 / 变量分开，用 `[` `]` 切）（大改，不推荐）

```
[变量] [栈] [监视]        ← 树内三个区
```
- 优点：栏窄时不用上下滚
- 缺点：跟"一眼看全""不要多一套键"这两条既有设计目标冲突；变量区与栈是**父子关系**（变量属于当前帧），拆成平级区会丢上下文
- 工作量 1.5 天+
- 结论：**不建议**。真要省地方，用 `max_frames`/折叠更划算。

## 5. 需要你拍板的三个小选择

| 选择 | 选项 | 我的建议 |
|---|---|---|
| ① 顶部 `a=2 b=3 s=5` 摘要 | 删掉 / 保留 / 改成配置项（默认关） | **留一个配置项、默认关**（有人就喜欢不展开就看一眼） |
| ② `全局`/`寄存器` 为空时 | 隐藏 / 显示但暗色 | **隐藏**（少两行噪音） |

## 8. 实现记录（与方案的偏差）

| 项 | 方案 | 落地 |
|---|---|---|
| 分组标签 | 纯中文 | **默认英文**（你定的），`[plugins.dapui] labels = "zh-CN"` 切中文 |
| 顶部摘要 | 配置项默认关 | 同（`locals_summary = false`） |
| 空作用域 | 隐藏 | 只在 adapter **明确报 0** 时隐藏（`namedVariables === 0`）—— lldb 的 `Globals/Registers` 不报数，仍然显示 |
| 类型列 | 右对齐 | 改成**紧跟值**（右对齐在宽栏里会拉出大片空白）；值优先：值至少 12 列，类型放不下就**整段省略** |
| 表头 | B 里有 | **没做**（先看效果；多一行在窄栏里不值） |
| 树宽 | 34 → 40 | 同 |
| 长值 | `…(+N)` | 同（`fit_value`） |
| 缩进 | 每级 2 列、最多 3 级 | 同，第 4 级起画 `┆` 提示 |

**列宽算法**（`compute_columns`）：缩进按**可见节点最大深度**算（各列必须共用一套）→
名字列 = `min(最长名字+1, 45%)` → 值列 = 剩余（≥12）→ 类型列 = 剩下给它的（放不下就省略）。

**新增配置**：`labels`（en|zh-CN）、`locals_summary`（默认 false）；`panel_size` 默认 34→40。

**测试**：`树排版：名字/值/类型三段分开`、`长值截断标出 (+N)`、`分组名语言 zh-CN`，加既有 58 条。


## 9. 同一套排版用到断点页（顺手）

`bp_label` 原来把 `路径:行 · cond: … · log: …` 拼成一条字符串；现在拆成
`bp_parts`（mark / where / cond / log / note）+ `bp_spans`（富文本三段），列宽按整页最长内容算：

```
 ●  multi/main.c:4    条件: v > 0
 ●  multi/main.c:9    日志: i={i}
 ◯  lib/twice.c:2     !no location
```

- 路径取**末两段**（`multi/main.c`）：紧凑 + 能区分同名文件
- 未验证用 `◯` + adapter 的 `message`（红）
- 空态提示改成 `F9 / <space>G b`


## 10. 三件收尾（2026-10-28）

| 项 | 做法 |
|---|---|
| **列头**（方案 B 的最后一块） | `[plugins.dapui] columns_header`（默认 **off**）：开时在树顶多画一行 `name = value type`，用与正文**同一套列宽**；文案跟 `labels` 走（`名字 = 值 类型`） |
| **监视失败太吵** | 值位置只放 `?`；完整原因进右列暗色提示，`short_err()` **从中间截**（lldb 的 `<user expression 1>:1:1: use of undeclared identifier 'v'` 有用信息在尾巴，只截尾会丢掉） |
| **空作用域** | 展开后拿到 0 个变量 ⇒ 标 `(empty)`（lldb 的 `Globals`/`Registers` 常常空，别让人以为还在加载） |

**测试**：`监视失败：值列只显示 ?`、`空作用域标 (empty)`（自造桩：`eval` 返回 `Error` 实例 ⇒ rejected promise，与真机一致）。


## 11. 三条反馈修复（2026-10-28）

| 反馈 | 根因 | 修法 |
|---|---|---|
| 重启 hx 后监视 `a` 还在，且换了程序就报错 | 监视存**全局一份** `~/.cache/helix/dapui-watches` | 改成**按工作区**：`dapui-watches-<cwd 的 slug>`；另给 `persist_watches = false` 彻底不落盘 |
| 右侧栏那条"颜色带"跟选中行分不清 | 选中行整行铺 `ui.selection`（且面板**没焦点**时也铺）；顶部会话行整行 `ui.text.focus` | 选中行加 **`›`** 记号；只有面板有焦点才用 `ui.selection`，否则 `ui.text.focus`；顶部行改成分段（徽标亮 + 摘要暗），不再整行铺底色 |
| `a` 后面一大串空格再 `= 0` | 名字列宽取"可见节点最长名字"，而**监视表达式**算在里面（一条长表达式能把整栏撑开） | 监视节点打 `is_watch`：不参与名字列测量、也不按列 padding（按 `表达式 = 值` 单独排版，表达式最多占 45%）；名字列上限 20 |

**顺手**：`cfg()` 只返回用户显式写过的键 ⇒ 新增 `bool_opt()` 兜默认值（`columns_header`/`locals_summary`/`persist_watches` 都受影响）。


## 12. "还有底色 / 还有很多空格" —— 用抓帧量出来了（2026-10-28）

用 pyte 抓每个 cell 的 `bg` 才发现：**`ui.text.focus` 在用户主题里带 `bg = 323843`**
（默认主题里没有），于是"帧 / 作用域 / 分组 / 会话行"每行背后都有一条色带，
和选中行的 `ui.selection` 撞色 ⇒ 看上去分不清。

| 修改 | 前 → 后 |
|---|---|
| 帧/作用域/分组/会话行样式 | `ui.text.focus`（带 bg）→ **`ui.text`**（无 bg） |
| 选中行 | 只靠 `ui.selection` 铺底 → **`›` 记号在最左固定列** + 面板有焦点时才铺底 |
| 缩进 | 每级 2 格 → **每级 1 格**（深度靠 `▾/▸` 读） |
| 名字列 | 由"变量 + 帧"共同决定 → **只由变量决定**（帧用右对齐位置，不该撑宽名字列）；宽度 6→14 |
| 前缀顺序 | `缩进 + 记号 + 折叠符` → `记号 + 缩进 + 折叠符`（记号永远在最左） |

结果（同一个例子，抓帧确认**全栏 bg 一致**）：

```
 #1  t752138
›▾ Watches (1)
    (a + b) * 100 + 12 = 1234568390
 ▾ add()                       hello.c:4
  ▾ Locals
     a    = 2  int
     b    = 3  int
```


## 13. 又一轮优化（2026-10-28）

| 项 | 改动 |
|---|---|
| **会话行加上程序名** | 核心 `dap_sessions_json` 多给一个 `program`（从**启动参数**里取 basename，adapter 配置里没有），树头变成 `#1 ⏸ t123 · rsdbg` |
| **树底部键位提示** | 只在面板**有焦点**时画一行（`j/k 移动 · l/Enter 展开 · w 监视 · e 设值 · y 复制 · / 过滤 · q 关`），没焦点不占行 |
| **值与类型重复** | `trim_value()`：lldb 对 struct/Vec 常给 `rsdbg::Point @ 0x7fff…` 或"值就是类型名" ⇒ 简化成 `…`（展开就有字段）；`Type { … }` 只留 `{ … }` |
| **"面板有焦点"的判断** | render 的 `focus` 参数是**JS 节点**焦点（draw API 没有节点 ⇒ 永远 null）。改成自己记 `FOCUS.where`（`focus_panel` 置位、`focus_editor` 清空）—— 之前"选中行亮底/底部提示"其实一直没生效 |

**实测**：`p = …` · `v = …`（不再有 `rsdbg::Point @ 0x…` 这种重复）；树头 `#1 ⏸ t771150 · rsdbg`；有焦点时底部一行提示。


## 14. just-my-code + 树内搜索跳转（2026-10-28）

### `just_my_code`（默认关）

- 触发条件：`reason === "step"` **且** 落点帧的源码不在工作区（`helix.cwd()` 前缀判断）
- 动作：`helix.dap.request("stepOut", { threadId })`，最多 **12 跳**（防递归/异常时死循环）
- 不触发：断点 / 异常 / attach 停住 —— 那些必须原地停给人看
- 落回自己代码时提示一次：`dapui: 已跳过 N 层库代码（just_my_code）`
- `stepOut` 失败（adapter 不支持）⇒ 直接把跳数打满，不再重试

**实测**（`/tmp/rsdbg`，连按 4 次 `s`）：停在 `sum() main.rs:4`，提示"已跳过 1 层库代码"。

### 树内搜索跳转

之前 `/` 只是**过滤**（递归保留祖先、自动展开），光标不跳。现在：

| 行为 | 说明 |
|---|---|
| `/` | 输入后过滤 + **光标跳到第一个"自己命中"的节点**（祖先节点只是承载，不占命中）|
| `n` / `N` | 下一个 / 上一个命中（循环）；**没有搜索时返回 `ignore`** ⇒ 仍然回落到全局的 `n`（单步跳过）|
| 命中数 | 状态栏 `搜索: y（2 处；n/N 跳下一个/上一个）` |
| 空结果 | 树里显示一行 `没有匹配: xxx`（而不是空白面板）|

**单测**：`just_my_code`（step 触发 stepOut / breakpoint 不触发）、搜索（递归保留祖先 + 光标跳转 + 循环）。


## 15. 浮层样式统一（2026-10-28）

`ask_text` / `ask_multi` 原来用 `helix.el("col", …)` 拼纯文本（没有边框，和 `picker-ui`
的圆角弹窗完全不同观感）。现在两者都改成 `helix.draw`：

| 元素 | 样式 |
|---|---|
| 边框 | `draw.rect(…, { border: "round", title, style: "ui.popup" })` —— 与 `picker-ui` 同款 |
| 标题 | 输入框的标题就是 `ask_text` 的 `title`（`监视表达式（每命中一次重算）` / `条件 f.c:4` …）|
| 分隔线 | `draw.hline(1, 2, w-2, { style: "ui.virtual" })` |
| 输入行 | `> ` 暗色 + 值 + `█` 焦点色；超宽**保留尾部**（前面 `…`），光标永远在最后 |
| 底部提示 | `ui.help`：`Enter 确认（空串 = 清除该项） · Esc 取消` |
| 多选 | 同上 + 每行 `› [x] 标签`（选中行 `ui.selection`），`Space/Enter 勾选 · j/k 移动 · Esc 保存关闭` |

**分工（"全局协调"）**：贴着屏幕边的**面板**用核心的直角框；浮在内容之上的**浮层**
（picker-ui、dapui 输入/多选）统一圆角框 —— 一眼能区分"贴边的"和"浮起来的"。


## 16. `v`（变量弹层）重做（2026-10-28）

用户反馈"`v` 显示的东西有点乱"。原来是核心 `Popup::new("dap-variables", Text)`：把每个作用域
和它的直接成员**平铺成一段文本**（`name: type = value`），没有缩进/列对齐，长值直接把行撑爆，
而且寄存器几百项一起灌进来。

改成**浮层 Picker**：

| 项 | 现在 |
|---|---|
| 形式 | `overlaid(Picker)` —— 和配置 picker 同一种浮层观感 |
| 排版 | 自己算两列宽（名字/值，按**全表最长** + 显示宽度感知）拼成一行：`名字  值  类型` |
| 为什么不用多列 | picker 的多列列宽 = 数据宽度，表头（`名字`/`值`）会被折成 `…`，反而更乱 |
| 寄存器 | `Registers` 作用域**跳过**（要看去面板里展开） |
| 空作用域 | 不占行 |
| 回车 | 复制值到 `"` + 系统剪贴板（与面板 `y` 同款），状态栏提示，列表留着继续看 |
| 其它 | picker 自带 j/k、输入即过滤、Esc 关闭 |

**实测**：`v` → `p 0x00007fffffffecd0  Point *` / `total 3  int`，回车 → `已复制 p = 0x…`。


## 17. 监视持久化：默认改成"不跨重启"（2026-10-28）

用户两次反馈"重启 hx 后上次的监视还在"。根因不是 bug，是**我上一轮加的功能默认开着**：
按工作区存到 `~/.cache/helix/dapui-watches-<cwd slug>`，同一目录再开会读回来。

判断：监视表达式更像"这一轮调试想看什么"，不像"项目配置"（VS Code 那种存法对多数人太重）。
⇒ **默认 `persist_watches = false`**（会话内有效），要跨重启自己开。

- 用户 config 里显式写了 `persist_watches = false`
- 已删掉遗留的 `~/.cache/helix/dapui-watches-*`（含旧的全局那份）
- 单测里那条持久化用例改成显式传 `{ persist_watches: true }`


## 18. 面板重开的落点（2026-10-28）

用户发现的设计问题（确实是问题）：关掉右栏后再打开，右栏只在**当前焦点所在的半块区域**里出现
（焦点在底部 ⇒ 右栏只有半屏高；焦点在右栏 ⇒ 底部只占编辑区那一列）。

**根因**：`open_panel` 默认是"在**当前活动叶**上分裂"（`split_leaf_with_ratio`），
而 dapui 之前刻意不用 `rail`（全局只有一条 rail，会和 filetree 互相驱逐）。

**修法（两侧各一半）**

| 面板 | 做法 |
|---|---|
| 右栏（树） | 打开前先 `focus_editor()` ⇒ 以**编辑器叶**为锚点分裂 ⇒ 右栏 = 编辑区右边的全高列。不用 `rail`（避免驱逐 filetree） |
| 底部 | 核心新增**底部停靠**：`WindowTree::register_dock_bottom()`（与 `register_rail` 对称，把整棵树包成 V 分屏），`open_panel({side:"bottom", rail:true})` 走它 ⇒ 横跨整宽 |

底部为什么必须走核心：JS 侧无论把焦点放哪，都只能"分裂某一个叶"，做不到"分裂根"。

**实测（release）**：关右栏 → 焦点进底部 → 重开右栏 ⇒ 右栏仍是全高列、底部仍横跨整宽；
关底部 → 焦点在右栏 → 重开底部 ⇒ 底部横跨整宽。

## 1. 跨边界的三种入口（本文件骨架）

| 类别 | JS 侧成员 | 跨边界机制 | Rust 落点 |
|---|---|---|---|
| **同步快照**（立即返回，可能略旧） | `sessions()` `list_breakpoints()` `configs()` | 宿主缓存 JSON（照 `cache_buffers` / `buffers_json`，`helix-js/src/state.rs:1041`） | 事件处理与每帧 `host.cache_dap_snapshot(json)` |
| **动作 / 查询**（Promise） | `launch` `attach` … `eval` `request` | `JsPromise::new_pending` + `DapRequest{id,kind,params}` 入 `h.dap_requests`（照 `helix-js/src/lsp.rs:99-118`） | `Application::pump_term_events`（`application.rs:455`）段 A/B → `DapResult{id,result}` 经 `WakeSender` 泵回 → `host.resolve_dap` |
| **事件**（单向） | `helix.on("dap-stopped", cb)` | 事件白名单（`helix-js/src/commands.rs:3-38`）+ `emit_dap_*`（照 `diagnostics.rs:24`） | 状态变化点（`handlers/dap.rs`）调用 |

### 1.1 五个必须照做的实现细节（否则"按了没反应"\)

1. **早退路径**：新队列必须同时加进 `pump_term_events` 的"空事件早退"判定
   （`application.rs:479-483` 的 `term_events.is_empty() && …`）。只加 drain 不加判定 ⇒
   单独到达的 DAP 结果被早退吞掉 ⇒ Promise 永不兑现（LSP 那段注释就是为此写的）。
2. **顺序**：段 A（results → 先应用副作用再 resolve）**必须**在 `pump_jobs()` 之前；否则
   `.then/.catch` 要等下一帧（同 `lsp_results` 的处理位置）。
3. **属主绑定**：注册期 `permissions::bind_callback(CbKey::dap_promise(id))`，并在
   `permissions.rs` 加 `CB_DAP` 常量 + `CbKey::dap_promise(id)`。否则插件卸载后 Promise 的
   `.then` 仍会跑（回调泄漏），且 `:plugin-unload` 回收清单里漏掉这一类。
4. **借用冲突**：`dap_requests` 的执行需要 `&mut self.editor`（启动会话 / 设断点 / 切会话），
   不能学 `handle_lsp_request(&self.editor, req)` 只借不可变；且**不能与 `self.js_host` 的
   `&mut` 重叠** ⇒ 顺序固定为 `take`（借 host）→ 执行（借 editor）→ `resolve`（借 host）。
5. **无会话不静默**：`id` 省略取 active；active 为空 ⇒ **reject** `"没有活动调试会话（先 :debug-launch 或 helix.dap.launch）"`。
   这条替代现在 `debugger!` 宏的静默 `return;`（`helix-view/src/handlers/dap.rs:17`）。

## 2. API 表（逐成员）

约定：
- **arity** = 声明表里的 arity（`helix-js/src/api.rs` 的 `e(Target::Ns("dap"), …)`），超参不报错、**类型错必须 TypeError**（入队前校验，别把坏参数送过边界）。
- `id` 一律**可选尾参**；省略 = active 会话。
- 路径一律**绝对路径**（`helix.dap.set_breakpoint` 传相对路径 ⇒ TypeError 提示用 `helix.fs` 的绝对形式；内核不做 cwd 相对解析）。
- 编码：`row` **0 起始**（与 `helix.set_virtual_text` / `helix.lsp.*` 一致）；DAP 协议的 1 起始换算在桥里做，**不外泄**。
- 所有成员 `caps`：`launch` / `attach` 需要 `process`（起 adapter 子进程）；其余 `&[]`。

| 成员 | arity | 参数校验 | resolve 值（JSON） | reject 条件 | 实现 |
|---|---|---|---|---|---|
| `sessions()` | 0 | — | 见 §3.1 | 永不 reject | 读快照缓存 |
| `configs()` | 0 | — | 见 §3.2 | 同上 | 读快照缓存 |
| `launch(name?, args?, id?)` | 3 | `name` string\|omit；`args` object\|omit | `SessionInfo` | 无 adapter / 模板不存在 / workspace 不受信 / adapter 启动失败 / initialize 失败 | `DapIntent::Launch` |
| `attach(name?, args?, id?)` | 3 | 同上 | `SessionInfo` | 同上 | `DapIntent::Attach` |
| `terminate(id?)` | 1 | `id` number\|omit | `null` | 无会话 / 不支持 terminate | `client.terminate()` |
| `restart(id?)` | 1 | 同上 | `SessionInfo` | 无 `supportsRestartRequest` / 无 `starting_request_args`（沿用现有两条检查） | `client.restart()` |
| `continue(id?)` / `pause(thread?, id?)` / `step_in(id?)` / `step_out(id?)` / `next(id?)` | 2 | `thread` number\|omit（缺省用会话当前 thread） | `null` | 无会话 / 无当前 thread（且未给 thread） | 对应 request |
| `threads(id?)` | 1 | — | `[{id,name}]` | 无会话 / 不支持 threads | `Threads` |
| `stack_frames(thread, id?)` | 2 | `thread` number **必填** | `[{id,name,source?,line,column,end_line?,end_column?}]`（**0 起始**） | 失败同上 | `StackTrace` |
| `scopes(frame, id?)` | 2 | `frame` number 必填 | `[{name,variablesReference,expensive}]` | — | `Scopes` |
| `variables(ref, id?)` | 2 | `ref` number 必填 | `[{name,value,type?,variablesReference,namedVariables?,indexedVariables?}]` | — | `Variables` |
| `eval(expr, frame?, id?)` | 3 | `expr` string 必填（空串 ⇒ TypeError） | `{result,type?,variablesReference}` | 无 frame 且无 stopped 上下文 | `Evaluate` |
| `set_breakpoint(path, row, opts?)` | 3 | `opts = {condition?,hit?,log?}` 全 string\|omit | `null` | adapter 不支持对应能力（沿用 `breakpoints_changed` 的三条 capability 检查） | 改 `BreakpointStore` + `setBreakpoints` |
| `remove_breakpoint(path, row)` | 2 | — | `null` | — | 同上 |
| `list_breakpoints(path?)` | 1 | `path` string\|omit | 见 §3.3 | 永不 reject | 读快照缓存 |
| `clear_breakpoints(path?)` | 1 | — | `null` | — | 清 + 推 `setBreakpoints` |
| `set_exception_breakpoints(filters)` | 1 | `string[]` | `null` | 无会话 | 替换现在的 `dap_enable/disable_exceptions` |
| `request(name, args?, id?)` | 3 | `name` string 必填 | 原样 DAP 响应 `body`（未知命令/无 body ⇒ `null`） | DAP error 响应 ⇒ reject（带 `message`） | **逃生口**：`client.request_raw(name,args)` |

> `request` 的边界：桥只做"发出去 + 原样回来"，不做类型映射；这是"新能力不必改核心"的代价
> —— 它对 adapter 乱来的容错为零，故文档里标注 **进阶用法**。

## 3. 快照 JSON 形状（字段级 —— 这是 d.ts 的另一半事实）

### 3.1 `sessions() → SessionInfo[]`

```ts
interface SessionInfo {
  id: number;
  name: string;                 // adapter name（languages.toml 的 debugger.name）
  config?: string;              // 启动用的 launch 配置名（P1 里来自 languages.toml 模板）
  state: "starting" | "running" | "stopped" | "terminated";
  active: boolean;              // 是否当前默认目标
  thread?: number;              // 当前 thread
  frame?: { id: number; name: string; line: number; column: number };  // 0 起始
  reason?: string;              // Stopped.reason（breakpoint/exception/step/…）
}
```
快照写入点：会话 created/removed、`stopped`、`continued`、`terminated`、`set_active`。

### 3.2 `configs() → DapConfigInfo[]`

```ts
interface DapConfigInfo {
  name: string;
  request: "launch" | "attach";
  language?: string;                       // 从哪门语言来的（lang 来源才有）
  source: "lang" | "toml" | "json";        // P1 **只有 "lang"**；P2 加另外两种
  adapter: string;                         // 目标 adapter 名
}
```
> P1 的一致性承诺：`configs()` 的结果与 `:debug-launch` Picker **同源同序**（同一个函数产出），
> 避免"命令里能看到、API 里看不到"。

### 3.3 `list_breakpoints(path?) → BreakpointInfo[]`

```ts
interface BreakpointInfo {
  path: string; line: number;              // 0 起始
  condition?: string; hit?: string; log?: string;
  verified: boolean;
  message?: string;                        // adapter 给的说明（如 "no executable"）
  id?: number;                             // adapter 分配
}
```
排序：`path` 字典序 → `line` 升序（稳定，UI 可直接渲染）。

### 3.4 缓存实现

- 宿主状态加两个字段：`dap_sessions: RefCell<String>`、`dap_breakpoints: RefCell<String>`
  （照 `state.rs` 的 `buffers_json` 形状），`host.cache_dap_sessions/cache_dap_breakpoints`。
- 读路径**不做 IO、不查编辑器**（纯缓存），所以 `sessions()` 可以在 render 里每帧调。
- 脏点必须收敛成**一个**函数 `Editor::refresh_dap_snapshot(&mut self)`（在 `handle_dap_intent`
  与 `handle_debugger_message` 的出口各调一次），避免"忘记刷某一处"。

## 4. 事件（9 个）

事件白名单在 `helix-js/src/commands.rs:3-38`；**加事件必须同步** `docs/plugin-api.md` 的事件索引块，
否则 `cargo xtask api-check` 会红（它校验"21 个事件都在文档里"，加完变 30）。

| 事件 | payload | 触发点 |
|---|---|---|
| `dap-session` | `{id, kind:"created"\|"removed", name, state}` | `Registry::start/remove` 之后 |
| `dap-stopped` | `{id, reason?, thread_id?, text?, all_threads_stopped?}` | `Event::Stopped` 处理完（栈帧已拉取）**之后** |
| `dap-continued` | `{id, thread_id?, all_threads_continued?}` | `Event::Continued` |
| `dap-exited` | `{id, exit_code?}` | `Event::Exited` |
| `dap-terminated` | `{id, restart?}` | `Event::Terminated`（重启由用户命令触发，不自动） |
| `dap-output` | `{id, category, output}` | `Event::Output`（**不缓冲**，直接发；REPL/Output 面板自己攒） |
| `dap-thread` | `{id, reason, thread_id}` | `Event::Thread` |
| `dap-breakpoint` | `{path, line, verified, message?, id?}` | `setBreakpoints` 响应回填 + `Event::Breakpoint` |
| `dap-progress` | `{id, kind:"start"\|"update"\|"end", text, percentage?}` | `Event::ProgressStart/Update/End`（复用 `client.progress_*`） |

约定：
- payload **扁平**（不塞 `body` 原样对象）：让 d.ts 能写死字段；要原样体的用 `helix.dap.request`。
- `dap-stopped` 必须在栈帧抓取完成**之后**发（否则 UI 收到事件去 `stack_frames()` 会拿到空/旧），
  这是现在 `Event::Stopped` 分支的实际顺序，别改。
- 事件里 `id` **总是**带（多会话必需），与 LSP 事件的 `docId` 同风格。

## 5. 能力（caps）与文档门禁

- `api.rs` 表里 `launch`/`attach` 写 `&[CAP_PROCESS]`（起 adapter 子进程）；**忘记写 = 无能力要求**，
  而派发点按表执行 ⇒ 等于给所有插件开了起进程的口子。`check_capability_surface.mjs` 会抓
  "函数体碰进程但表里没声明" 的哨兵，但仍要主动写。
- 新增 `dap` 命名空间的 17 个成员后必须一次性做完四件事（否则 CI 红）：
  1. `plugins/helix.d.ts` 补 `dap:` 块 + `SessionInfo/DapConfigInfo/BreakpointInfo` 等接口；
  2. `docs/api/dap.md` 新文件（逐成员）；`docs/plugin-api.md` 的总索引块与事件索引块各补一行；
  3. `cargo xtask api-check`；
  4. `docs/api/dap.md` 里明确写"`row` 0 起始"和"`request` 是进阶逃生口"。

## 6. `dapui` 插件与 API 的契约

> 面板几何 / 状态机 / 键位 / 空态规则见 [`2026-10-25-dapui-layout.md`](2026-10-25-dapui-layout.md)。

| 面板 / 行为 | 用哪些 API | 刷新方式 |
|---|---|---|
| 右 panel 变量树 | `stack_frames` `scopes` `variables`（懒加载：展开节点才拉） | `helix.on("dap-stopped"/"dap-continued"/"dap-terminated")` → 重拉根节点 |
| 底 panel REPL | `eval` | 用户输入 |
| 底 panel Output | `on("dap-output")` 自己攒环形缓冲（最多 500 行） | 事件驱动 |
| 断点列表 Picker | `list_breakpoints()` `remove_breakpoint` `set_breakpoint` | 打开时读一次 + `on("dap-breakpoint")` 增量 |
| 内联值 / 当前行 | `set_virtual_text` / `set_highlight`（`helix.d.ts:701,703`） | `dap-stopped` 时写；`continued` 时清 |
| statusline `dap` 段 | `sessions()` | 每帧读快照（纯缓存，零成本），多会话显示 `#id` |
| 会话切换 | `sessions()` + `:debug-sessions`（同一个 Picker 实现） | — |

- 组件渲染用 `set_component_render(id, fn, {pure:false})`：变量树依赖外部状态（会话/主题），
  **不能**声明 `pure:true`（声明错 = UI 不更新，见 `helix.d.ts:744-754`）。
- 插件 `define_config("dapui", {inline_values: boolean, auto_open: boolean, variables_max_depth: number})`，
  全部**每帧读**（`:config-reload` 即时生效）。

## 7. P1 明确不做（别提前实现）

- `configs()` 只有 `source:"lang"`（`.helix/launch.toml` 与 `.vscode/launch.json` 是 P2）。
- 不做请求级超时添加（沿用 `helix_dap::Error::Timeout`，由 client 层给）。
- 不做流式 `output`（一次事件一段，UI 自己攒）。
- 不做 `dap.request` 的类型化封装（想类型化就加新成员，别在 `request` 里猜）。
- 不做"未启动时设断点在 UI 上灰显"这类细节（P2 变量树/断点面板时再定）。

## 8. 可测性（P1 的验收靠这三层）

1. **`helix-dap` 单测**（P0 的假 adapter 接缝）：`request_raw` / capability 检查 / `BreakpointStore` 回填。
2. **`helix-js` 单测**：API 契约 —— 用 `JsHost::new()` 私有宿主，注入假快照 JSON 断言
   `sessions()`/`list_breakpoints()` 形状；用 `load_script` 断言 `launch` 在无会话时 **reject**
   而不是返回 null（Promise 的 `.catch` 收到消息）。
3. **`node --test`**：`dapui` 的纯渲染（桩注入 `global.helix`，照 `plugins/statusline/tests/` 写法），
   断言"stopped 后变量树出现根节点""continued 后内联值被清掉"。

# which-key 的取舍（设计建议）

> 你的问题：「显示不全 / 显示全又占地方 / 不全还有必要吗」——**这是个真矛盾**，
> 但根源是把它当成了"键盘字典"。它不该是字典。

---

## 1. 先把问题问对

which-key 每次弹出来，用户心里只有一个问题：

> **"我刚按了 `<space>`（或 `g`），下一个键能按什么？"**

它**不是**"这个模式一共有多少键"。所以：

| 你担心的 | 实际情况 |
|---|---|
| "显示不全" | 你**从来不需要**看到整棵树 —— 只需要看到**当前这一层**的子键 |
| "显示全占空间" | 一层子键通常在 5–20 个；20+ 的只有 `space` 这种顶层菜单 |
| "不全还有必要" | 有必要，但**只在"这一层子键多 / 你记不住"的时候**。`j/k/dd` 这种层弹出来纯属噪音 |

一句话：**问题不是"要不要全"，而是"什么时候提示、提示多少、剩下的去哪查"。**

---

## 2. 三条原则

### ① 渐进披露（progressive disclosure）
- **按键途中**：只显示当前一层，截断到"能塞下"的条数
- **刻意查询**：`?` 打开**完整**表（可滚动/可搜），占用空间是用户主动要求的结果

截断文案要**指路**，不要只说"还有 N 个"：
```
… 还有 7 个（按 ? 看全部）
```

### ② 频次优先（frecency）
截断谁都能做，关键是**截掉谁**。按"最近/最常按"排序，前 N 个就是你要的，
截断就变成"精准压缩"而不是"丢信息"。

存储：`~/.cache/helix/which-key-frecency`（一个 key→计数的 JSON，几百字节）。零维护。

### ③ 空间预算（默认 1 行，浮层要用户要）
| 形态 | 代价 | 什么时候用 |
|---|---|---|
| 状态栏一行 | 0 行 | **默认**。键名 + 当前选中项说明 |
| 1 行浮层 | 1 行 | 想让"键名条"更显眼（还能躲开面板） |
| 完整浮层 | 最多 `max_lines` 行 | 只给 `?` 显式触发，或 `space` 这种超顶层菜单 |

---

## 3. 推荐设计（三层，映射到你现在的实现）

| 层 | 触发 | 形态 | 现状 |
|---|---|---|---|
| **执行期** | 按了前缀键（`space` / `g` / `z` …） | **状态栏一行**：`space ▸ f 文件 · b 缓冲区 · g 变更 … +12` | 已有：`mode = "status"`（或 `line` 加 1 行浮层） |
| **探索期** | 显式按 `?`（或你配的键） | **buffer/浮层**：当前层全部键 + 说明，可滚可搜 | Debug 层已有（`?` → 键位表 buffer）；推广成通用 `:keys` 即可 |
| **专家期** | 配置 | `mode = "off"` | 需要加（一行判断） |

**判断"要不要弹"的启发式**（很重要，能解决"噪音"那一半）：

```
当前层子键数 < min_entries（默认 2）⇒ 不弹
当前层里所有键都在你的"高频集合"里 ⇒ 也不弹（都记住了）
```

---

## 4. 备选方案（不推荐，但列出来对比）

| 方案 | 问题 |
|---|---|
| **永远显示全部（box 不截断）** | 20+ 行的浮层会盖住你正在看的代码；而且 20 行里 18 个你根本不用 |
| **干脆不要（mode=off）** | 低频/歧义键（`space G`、`z` 折叠、`g` 跳转）就靠背 —— 这是最初"按键后一脸茫然"的来源 |
| **只显示在状态栏，永不留浮层** | 状态栏会被别的消息盖掉（我们踩过：dashboard / 构建输出） ⇒ 提示没了还以为是没绑定 |
| **每个前缀都配一个 `?` 子命令** | 要维护两份表，必然漂移（我们已经因为"两套键位表"改过一次） |

---

## 5. 如果你问"我会怎么配"

```toml
[plugins.which-key]
mode = "status"        # 0 行：状态栏一行，键名 + 说明
max_lines = 6          # 只有 box（`?`）时才用得上
on_debug_hint = "off"  # 调试命中那行也别弹（要看按 ?）
```

心智模型变成：

- **平时**：按 `<space>` → 状态栏出现一行候选，选就行，不占屏幕
- **不确定时**：`?` → 完整表（可搜），看完 `:bc` 关掉
- **熟练后**：把 `mode` 改成 `off`

---

## 6. 如果要我实现（预估）

| 改动 | 价值 | 工作量 |
|---|---|---|
| 截断文案指路（`… 还有 N 个（? 看全部）`） | 高（把"不全"变成"设计"） | 10 分钟 |
| `min_entries`（子键数 < N 不弹） | 高（消掉噪音） | 20 分钟 |
| 通用 `:keys`（`?` 打开当前层完整表成 buffer，复用 `debug_help` 那套） | 高（"全"的出口） | 1 小时 |
| frecency 排序（按最近/常用重排，前 N 更准） | 中 | 2 小时（含缓存文件） |
| `mode = "off"` | 低（一行判断） | 5 分钟 |

**建议顺序**：截断指路 → `min_entries` → 通用 `:keys` → frecency。

---

## 7. 一句话结论

> **别追求"显示全"**。让 which-key 只回答"下一步按什么"（一行、按频次排序、截断时指路 `?`），
> "全部"交给 `?` 现查现看。**占用空间是用户按 `?` 时才该付的代价**，不该是每次按前缀的默认税。

## 8. 实现记录（v2，2026-10-28）

| 项 | 落地 |
|---|---|
| **截断指路** | `cap_lines` → `… 还有 N 个键（:keys 看全部）`；`summarize` 也带同样的指路。文案可配（`keys_help_command`，空串关闭） |
| **`min_entries`** | 当前层子键数 < N 直接 `{hide:true}`（两条渲染路径都判：平级模式 & 普通 entries） |
| **通用 `:keys`** | 核心新命令（别名 `:keymap`）：三层同源 —— 平级模式用 `input_router::hints`；调试暂停用 `dap_keymap()`（含 `[keys.debug]`）；否则用**运行时** keymap（`set_runtime_keymaps` 快照，含 `[keys.normal]` 覆盖）递归展开，开成可搜可滚的 buffer（复用同一个 buffer） |
| **frecency** | 核心 `helix-term/src/frecency.rs`：命中键序列 → 计数（`space g b` 这种），每 25 次增量落盘 `~/.cache/helix/keys-frecency.json`，上限 512 条；JS 通过新 API `helix.key_frecency()` 读（**回调式**，只有渲染提示时才取一次） |
| 版本 | `helix.plugin("which-key", { version: "2.0" })` |

**顺带**：`PaneMode` 加了全局镜像（`input_router::set_current_pane_mode`），因为 typed 命令拿不到
`Compositor::pane_mode()`，而 `:keys` 需要知道"现在在不在平级模式里"。

**验证**：`space` → 浮层显示 `… 还有 19 个键（:keys 看全部）`；`:keys` → 当前层完整表（递归 + 缩进）；
敲 30 次 `j` → `~/.cache/helix/keys-frecency.json` 出现 `{"j":25}`；which-key 单测新增 3 条
（截断指路 / min_entries / frecency 排序）。

## 9. "已经有 `space ?` 了，还要 `:keys` 吗？"

**要 —— 两者不是一回事**（`space ?` 在这套键位里是**命令面板**，不是键位表）：

| 入口 | 实际内容 |
|---|---|
| `<space>?` | **命令面板**（按命令名搜命令，`command_palette`）|
| `?`（编辑器 Normal） | `rsearch`（反向搜索）|
| `?`（**调试暂停**时） | 键位速查（只有 Debug 那一层） |
| **`:keys` / `<space>K`** | **当前层的完整键位表**（普通层 / 平级模式 / 调试层三选一）|

所以 `:keys` 补的是两块空白：
1. **普通层 / 平级模式**没有"看全部"的入口（`?` 在普通层是搜索，在平级模式里也进不去）；
2. which-key 截断时的「还有 N 个」**需要一个落点**，否则那句话就是死胡同。

**可发现性补齐**：除了 `:keys`，还在 `<space>` 菜单加了 **`<space>K`**（K = Keys，这个键原来是空的）
—— 它和 `:keys` 是同一个命令，并且会在 which-key 的 `space` 提示里**自己出现**。
平级模式里 `space` 进不去（键被那一层吃掉），所以那种情况仍然用 `:keys`（提示文案里写的也是命令，不是键）。

## 三、布局树(zellij 化)——核心

### Rust 原语(`layout.rs` + `compositor.rs`)
- `resize_leaf_dir(id, dir, delta)` 方向感知调比例(只调直接父 Split,方向匹配才生效)
- `swap(id1, id2)` 只换 components 表引用(树/焦点/比例不动)
- `set_minimized(id, bool)` 最小化(不占布局,底部标题横条)
- `neighbor_leaf(id, dir, first_side)` 方向邻居(祖先链回溯 + extreme_leaf 极值)
- `focus_dir` / `swap_dir` / `equalize`
- **焦点高亮边框**:`draw_focus_border`(ui.popup 色,活动叶子 inset 1 格,浮窗/zoom 不重复)
- **get_layout 缓存同步**:所有布局操作后 `sync_layout_cache`(Compositor 方法统一调用;漏了会导致 JS 读 stale active)

### JS API
`helix.layout_resize(id,"h"|"v",delta)` / `layout_swap` / `layout_minimize` / `layout_focus(id,"left"|...)` / `layout_swap_dir` / `layout_equalize` / `zoom` / `focus` / `close_leaf` / `get_layout`

### 布局模式:统一到 C-w 组
- **历史**:先做 C-space w(compositor 拦截,任何焦点可用)→ 用户决定统一 C-w
- **C-w 组**(`features/which-key.js`,编辑器 normal):h/j/k/l 焦点、H/J/K/L 交换、`< > + -` 宽/高±5%、`=` 均衡、z 全屏、o 最小化、q 关闭、t/f term/filetree
- **infobox(which-key 效果)**:helix 原生,命令 doc 来自 `register_command` 第三参
- **边界**:终端/面板焦点 C-w 被吞(终端 C-w=readline 删词),先 C-\ 回编辑器;终端 C-\ ×2 回,filetree C-\ ×1 回(新加)
- **C-space w 拦截已删除**(compositor.rs 无残留)

## 四、filetree 崩溃修复(重要)

用户报 `<plugin panel error: popup 1 not open>` + 无法关闭,两层根因:

1. **ClosePanel 用 popup id 当布局树 leaf id**:单面板时两 id 碰巧相同才工作;多面板/终端混排时错删或删不掉。修复:按 popup id `find_leaf_id::<PluginPanel>(|p| p.id()==id)` 再 remove_leaf(typed.rs + plugin_panel.rs 自愈路径)
2. **reload 只关 last_panel_id**:残留面板变僵尸(JS 注册表清空后 render/onKey 报错)。修复:
   - `OPEN_PANELS` 全局 id 列表(非 thread_local!打开与 reload 可能跨 tokio 线程),reload 全部关闭
   - **僵尸自愈**:`popup_exists` 检测 + 按键自动移除面板(close_panel_state)
   - reload 重跑失败(Err)也处理 ClosePanel

# 改动纪律

## 概述

**在既有代码库里,写对的难点通常不是"想不到怎么写",而是"以为知道了,其实不知道"。**

本技能把这类失败归纳成一条主线:

> **凡是"看不见"的东西,都会骗你。**
> 看不见的错误(静默吞掉)、看不见的语义(没读实现就动手)、
> 看不见的范围(没测规模就承诺)、看不见的覆盖(以为 check 等于 test)。

配套四条操作纪律:**先读再改 · 让失败可见 · 分层验证 · 失败即回退**。

**适用**:改动陌生/半陌生代码库、跨文件或多层改动、照着文档或记忆写 API 调用、以及任何一次改动已经开始"反复失败"的时刻。

---

## 一、先读再改(不信记忆,不信文档,更不信猜测)

**动手前必须做的三件事,顺序不能换:**

1. **grep 符号名,读实现** —— 不是读文档、不是读印象。
2. **找既有同类实现照抄** —— 你想做的事,代码库里**几乎总有一处已经做对了**;
   把它当模板,而不是自己设计形状。
3. **量规模再承诺** —— 说"这是个小改动"之前,先数一遍真正要改的点。

**为什么**:"我以为它是薄接口"和"它其实是全局表"之间,差的往往是一个数量级的工期。

### 反例表(每条都真实发生过)

| 我的假设 ✗ | 实际 ✓ | 正确做法 |
|---|---|---|
| "把作用域参数透给这个管道就行(~20 行)" | 那个"每视图"的管道**就是全局表** ⇒ 要改**派发核心** | 承诺前先读那 10 行实现 |
| "解绑用 `no_op` 顶替即可(~10 行)" | `no_op` 会**吞掉按键** ⇒ 键变死键 | 需要真正的移除逻辑;先验证语义再估工 |
| "`contains_key` 就是'该键是否已绑'" | 它是"**给定 pending 前缀后**该节点是否含此键" ⇒ 空前缀**恒 false**,且模式缺失时**索引 panic** | 读实现的文档注释与既有测试的**探针选择** |
| "空表也能插入绑定" | 那个 insert **只 merge 进已有模式** ⇒ 空表永远合不进去 | 看既有测试**怎么构造**被测对象,照抄 |
| "把命令常量用在模式匹配里" | 它是**函数指针** ⇒ 不能用于 `matches!` | 用**值比较**(`assert_eq!`) |
| "`let x = 对象` 就够" | 取数方法取了 `&mut self` ⇒ 必须 `let mut` | 编译器的错就是答案,别绕过 |
| "写内容调顶层 `insert`" | 编辑方法挂在 **`ctx.doc`** 上(文档写了,我没读) | 先读该领域的 doc,再写调用 |
| "`ctx.doc` 指向我刚新建的那个 buffer" | 它在**处理器运行前**构造 ⇒ 指向**旧** buffer | 用"本来就该用"的那个对象,别新造 |
| "改了这个类型,跑主 crate 的 check 就够" | `--all-targets` **不覆盖依赖 crate 的测试目标** | 改了哪个 crate,就 `test` 哪个 crate |

## 二、让失败可见(最高杠杆的一步)

**静默的失败会浪费你几个小时;可见的失败会给你答案。**

| 反模式 ✗ | 替代 ✓ |
|---|---|
| 只写 `log::warn!(...)` | **推入用户可见的状态/消息通道**(状态栏、消息列表) |
| 用 `try { … } catch {}` 吞掉 | **捕获后必须报告**(打印、抛出、写入可见位置) |
| 让失败只在日志里 | 让失败出现在**你的断言输出**里 |
| 用管道 `cmd \| head` 看结果 | **先落文件 + 回显退出码**,再筛(管道会掩盖退出码) |
| 猜测"大概是 X 的问题" | **打印状态**,让程序说出 X |

**技法:panic-with-state(诊断型断言)**

把**当前的真实状态**放进 panic 消息里,一次运行就给出确切原因:

```
panic!("STATUS=[{status}] LEN={} TEXT={:?}", len, text)
```

实测对比:**靠猜测改 API 6 次 ✗ 零进展;靠这个技法 2 轮 ⇒ 2 个确切原因 ⇒ 2 个修复。** ✓

## 三、替换与补丁的安全

批量/脚本化改动最容易"悄悄改坏",把下面每条做成机械检查:

1. **锚点必须唯一,并断言计数** —— `assert count == 1`,否则**中止**而不是"尽力而为"。
2. **多文件补丁:要么全校验后一次落盘,要么逐文件写完。**
   中间态跨文件 = 树处于**编译不过**的状态(实测:只写了类型、没写构造方 ⇒ 树坏了)。
3. **别让格式化重排你的锚点** —— `fmt` 之后再改同一文件,锚点要**重新读**;
   需要精确单点修改时,优先用**编辑工具**而非"读全文再整段替换"。
4. **循环变量取不会混淆的名字** —— `l`/`L`、`1`/`l`、`O`/`0` 的笔误在脚本里高发;
   用 `lines`/`ln`/`item` 这类名字,笔误就消失了一大半。
5. **一条替换规则只做一件事,并且可反证** —— 改完后**独立校验**:
   旧名在新位置**零残留**、新名在旧位置**零出现**。
6. **正则要锚定到"活的代码"** —— 全局替换会连**注释里的示例**一起改
   (实测:探测脚本把我自己写的注释也改了 ⇒ 计数对不上)。
   当"安全地全局替换"不可能时:**打印决策清单,只替换确定的行**。
7. **别用会引入嵌套引号的写法** —— 在 shell/heredoc 里,优先"写文件"而不是"拼字符串";
   全角标点、弯引号会让脚本在解析前就失败。

## 四、分层验证(不同层钉不同东西)

| 层 | 钉住什么 | 例 |
|---|---|---|
| **单元测试** | 底层能力本身 | "摘除后不再命中我绑的命令" |
| **加载/接线护栏** | 新东西**能被解析和加载** | "新增的入口能被解析" |
| **独立验算** | 纯逻辑(不需要图形界面) | 把布局函数抽出来在 node 里跑,看输出对齐 |
| **端到端** | 用户实际路径 | "开屏后 buffer 无路径且含菜单文本" |
| **安全行为** | "不确定时不做"的闸门 | "有真实文件时**拒绝**绘制" |

**必查项:**

- **先确认被测物就位,再断言行为。** 否则你测的是"没加载",而不是"没生效"
  (实测:先断言"插件加载成功",才排除了整类误判)。
- **`check` ≠ `test`。** 编译通过不等于测试目标能编译/能过。
- **删掉假断言。** 没有实际断言的"占位块"应删除或补成真断言;
  否则它会在报告里伪装成"已验证"。
- **先跑一次大绿色基线。** 否则分不清"是我改坏的"还是"本来就这样"。
- **单线程复跑可疑失败。** 并发下的偶发失败先单线程定论,再决定是不是真 bug。

## 五、回退纪律

- **只动自己的文件。** 别人的模块/历史 import 之类,别顺手"清理"。
- **门禁失败即回退**(`git checkout <自己改的文件>`),**不留半截**。
  一次干净的回退 ≈ 零成本;一个"半对"的树 ≈ 后续每一步都在还债。
- **宁可"这次不做"。** 当"再做一步"需要靠猜、或预算已经见底时,
  **不做**是正解:它保持树干净,并把下一步变成"照已完成的地基继续"。
- **未验证的完成不算完成。** 声称完成前,必须有**你刚跑出来的**输出支撑。

## 六、规模测量(决定"现在做"还是"下一轮做")

对"看起来是大改"的活,先花一次查询**量出真实规模**:

```
需要改的变更点: 10 处
需要跟进的调用点: 38 处
```

然后二选一:

- **规模小** ⇒ 现在就做,但拆成**可独立验证**的小步(每步结束树是绿的)。
- **规模大** ⇒ **不要硬试**。改为:先只做**最有代表性的 1–2 个**,验证机制成立,
  剩下的变成"按同一模式一行一个"的纯增量。

**关键洞见**:"找对机制"能把一个多站点大改**降一个数量级**
(实测:把"改键位派发核心"换成"开屏绑/关屏解绑",从 ~67 处变成 ~2 + 7 处一行增量)。

## 七、一页速查

```
动手前:  grep 符号名 · 读实现 · 找既有模板 · 量规模
改之前:  锚点唯一+断言计数 · 逐文件或全校验后落盘 · 循环变量别用 l/L
改之中:  错误必须可见(状态栏/panic-with-state) · 不用 try/catch 吞
改之后:  先确认被测物就位 · 该 crate 就该 crate test · 独立验算 · 删假断言
回退时:  只动自己的文件 · 门禁失败即 checkout · 宁可不做不留半截
失败时:  不猜 —— 打印状态,让程序说出原因
```

> **一条主线:凡"看不见"的都会骗你 —— 让它可见,再动手。**

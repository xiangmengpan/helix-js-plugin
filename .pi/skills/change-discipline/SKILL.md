# 改动纪律

## 概述

**难点通常不是"想不到怎么写",而是"以为知道了,其实不知道"。**

主线:**凡"看不见"的都会骗你** —— 错误(静默吞)、语义(没读实现)、范围(没量规模)、
覆盖(以为编译通过=能用)、测量(工具错了却信读数)。
纪律:**先读再改 · 让失败可见 · 分层验证 · 失败即回退**。语言无关,技术只作例子。

---

## 一、先读再改(不信记忆,不信文档,更不信猜测)

顺序不能换:

① **搜符号名读实现**(不是读文档/印象)——文档常滞后,类型声明尤其易陈旧。
② **找仓库内先例照抄**——你想做的事几乎总有一处已做对。
③ **量规模再承诺**——说"小改动"前先数要改的点。

**估错的代价是一个数量级**:三次"看起来 10 行"的活,实际都远超。

### 反例表(真实发生过)

| 假设 ✗ | 实际 ✓ | 规则 |
|---|---|---|
| "参数透给这个管道就行" | 那个"每视图"的管道**就是全局表** | 承诺前读那 10 行 |
| "用现成的空操作顶替即可" | 空操作会**吞掉**输入(变死键) | 先验语义再估工 |
| "断言 A = '该项是否存在'" | 它是"给定前缀后是否匹配";空前缀恒假,缺失时还会崩 | 读注释与**既有测试的探针** |
| "空容器也能插入" | 那个插入**只合并进已存在的项** | 看既有测试**怎么构造**对象 |
| "常量可用于模式匹配" | 它是**函数指针** | 用**值比较** |
| "`x = 对象` 就够" | 取数方法要求**可变引用** | **编译器的错就是答案** |
| "写内容调顶层 `insert`" | 方法挂在**上下文对象**上(文档写了,我没读) | 先读该领域文档 |
| "上下文指向我新建的容器" | 它**在处理前构造** ⇒ 指向旧容器 | 用"本来就该用"的对象 |
| "跑主包检查就够了" | 那个开关**不覆盖依赖包的测试** | 改哪个包就 **test 哪个包** |

## 二、让失败可见(最高杠杆的一步)

**静默的失败浪费你几小时;可见的失败直接给答案。**

| 反模式 ✗ | 替代 ✓ |
|---|---|
| 只写日志 | 推入**调用方可见**的通道(状态栏/消息/返回值) |
| `try { } catch {}` 吞掉 | 捕获后**必须报告** |
| 抛异常就以为"报错了" | 异常**可能根本不可见**(UI/异步/被上层吞)⇒ 显式报告 |
| 管道 `\| head` 看结果 | **先落文件+回显退出码**,再筛(管道掩盖退出码) |
| 猜"大概是 X" | **打印状态**,让程序说 X |

**技法·诊断型断言**:把**真实状态**放进抛错消息,一次运行给出确切原因
(`throw("status={..} len={..} content={..}")`)。
实测:**靠猜改接口 6+ 次零进展;这个技法 2 轮 ⇒ 2 因 2 修。**

**技法·服从报错的指令**:报错写着"用某开关重跑以取栈/详情"就**第一件事去做**。
实测:我因此多花两轮才拿到栈,而栈一次指出真凶。

**技法·常驻诊断命令**(如 `:diag`):胜于每次临时打日志;排障后留精简版,删探针。

---

## 三、崩溃/异常:先复现,再修

① **先拿栈/回溯**(见上:服从错误指令)。
② **在自动化测试里复现**它 —— 能复现才谈得上修。
③ **变成回归测试**:修复前必崩、修复后必过(实测:最后一次修复之所以可信,正因有它)。
④ **不要手改内部结构去"修"**:既有流程能做的,照抄它的**完整流程**。
   但**照抄步骤也不够** ✗:同一流程在**不同调用环境/时机**下仍可能崩
   (实测:照抄某命令全部四步依然崩;真因是"渲染发生在检查之前"的**顺序**)。
   ⇒ 复用既有逻辑时,要复用**它的执行环境/调用路径**,而不只是语句序列。

---

## 四、替换与批量修改的安全

1. **锚点唯一 + 断言计数**:`assert count == 1`,否则**中止**,别"尽力而为"。
2. **断言替换数量符合预期**(过宽替换命中多处 ⇒ 有的位置没所需变量 ⇒ 运行期崩)。
3. **多文件补丁:全校验后一次落盘,或逐文件写完** —— 中间态 = 编译不过的树。
4. **别让格式化重排锚点**:格式化后改同文件要**重读锚点**;单点修改优先用**编辑工具**。
5. **临时/循环变量用不混淆的名字**:`l`/`L`、`1`/`l`、`O`/`0` 的笔误在高发区。
6. **改完立即复验**:旧名零残留、新名零误入,且每处新引用**在作用域内可见**。
7. **规则要锚定"活的代码"**:全局替换会连**注释里的示例**一起改 ⇒ 计数对不上。
8. **别拼嵌套引号**:能写文件就别拼字符串;全角/弯引号会让脚本解析前就失败。

## 五、分层验证(不同层钉不同东西)

| 层 | 钉住什么 | 例 |
|---|---|---|
| **单元** | 底层能力本身 | "移除后不再命中我加的那条" |
| **接线/加载** | 新东西能被解析与加载 | "新增入口能被解析" |
| **独立验算** | 纯逻辑(无需图形界面) | 抽出布局函数单独跑,看输出对齐 |
| **端到端** | 用户实际路径 | "打开后处于无路径状态且含菜单文本" |
| **安全行为** | "不确定时不做"的闸门 | "有真实文件时拒绝写入" |

**必查项:** 先确认被测物就位再断言行为(否则测的是"没加载" ✗) · **编译/语法通过 ≠ 语义正确**
(改完必须**执行到那条路径**;实测:语法检查通过却引入运行期错误) · **删掉假断言**(空占位块会伪装成"已验证") ·
**先跑大绿色基线**(否则分不清谁改坏的) · 可疑失败先**单次复跑**再定性。

## 六、核查你自己的工具

**错工具的读数会比没有读数更糟** —— 它会把你带向错误结论。

- **过严的模式 ⇒ 假阴性**:整行匹配式搜索会"什么都搜不到",而你会读成"它不存在"。
- **区分实时值与快照值**:两个"根因"其实是误读——一个是设计上就该空的值,
  一个是**构造时的快照**而非当前状态 ⇒ 探针必须能说清**它量的是哪一刻、哪个对象**。
- **行号必须带文件名**:实测把 A 文件的搜索结果当成 B 文件的行号,读了一堆无关代码。
- **核查完还要复验核查工具本身**:你的脚本/正则同样可能写错。

---

## 七、回退纪律

- **只动自己的文件**;别人的代码别顺手"清理"。
- **门禁失败即回退**(恢复版本库状态),**不留半截**:干净回退≈零成本,半对的树≈步步还债。
- **陈旧测试比没有测试更糟**:行为已变就删除并写待补说明,别留着装点门面。
- **宁可"这次不做"**:需要靠猜、或预算见底时,不做是正解——保持干净,把下一步变成"照地基继续"。
- **未验证的完成不算完成**:声称完成前必须有**你刚跑出来的**输出。
- **不给假信息**:宁可少显示,也别显示固定/伪造的值(实测:无真实时钟却显示时间)。

---

## 八、一页速查

```
动手前: 搜符号名读实现 · 找仓库内先例照抄 · 量规模再承诺
改之前: 锚点唯一+断言计数 · 全量校验或逐文件落盘 · 临时变量别用 l/L
改之中: 错误必须可见 · 不靠 try/catch 与抛异常 · 服从报错里的指令(如取回溯)
改之后: 先确认被测物就位 · 改哪个包测哪个包 · 独立验算 · 删假断言
崩了时: 先拿栈 → 测试里复现 → 变回归测试 → 复用既有流程(**含其执行环境**)
回退时: 只动自己的文件 · 门禁失败即恢复 · 宁可不做不留半截
测得时: 说清探针量的是哪一刻/哪个对象 · 核查工具本身
```

> **一条主线:凡"看不见"的都会骗你 —— 让它可见,再动手。**
